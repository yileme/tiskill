# dbskill 对标与 tiskill 的有界改进

## 判断与证据范围

dbskill 值得学的是明确的判断规则、能推动下一轮的动作、各技能不同的交付物，以及把方法接成产品的入口和安装更新体验。尖锐语气让它有辨识度，但不应把训斥复制到学习反馈。公开源码能支持这项设计判断，不能证明营收、留存或学习成效。

本次通过 GitHub API 取得 main 提交 `fe58a23f93203989ad6a1aef88c1cbb533491efc`，再读取该提交的 README、入口、diagnosis、content、jtbd 全文。README 标 3.0.1。本机 dbs 入口为 2.18.45，仅用于版本差异对照，未冒充最新源码。dbs-benchmark 使用已安装版本的五重过滤视角；利润/十倍门槛无法核实，不判通过，转而核对可理解、可执行的机制。其“排除自我”和不一致必错等信条不是普适原则，教育目的、证据和学习者约束应保留。

## 表达前后

以下“原要求”为 0.7.1 提示词中的真实文本；示例回复均是编写的验收目标，不是运行前后模型记录。

- 原要求：diagnosis “每次报告末尾增加‘这节课的元语言’”；现在仅完整报告要求，局部提问直接解释本处。示例：“‘has been approved’ 把‘尚未批准’写成已经批准了。按原文对照，改成 ‘has not yet been approved’ 即可。”
- 原要求：practice “输出‘任务分析卡 → 难点/候选/取舍 → 可试写版本或局部示范 → 译后自查清单’”；现在局部问题只给取舍。示例：“这里需要保留‘可能’，用 ‘may’；‘will’ 会把不确定结果写成确定结果。”这是原文对照，不冒充词典实查。
- 原要求：CAT “中文回答；不要虚构词典或用法查证”；现在增加具体片段、理由、最小改法及共享规则。来源失败时示例：“这次没能打开可核原文，我还不能把它判作已查证错误。”保留来源失败和未核实状态，不用口号替代证据。

去模板化参考已安装 humanizer-zh（保留信息、确定程度、文体与引文）及 lieflat-less-ai-tone（避免空转起手和虚构对比）；未把后者的频率统计或词表当成作者身份检测。本次独立编写任务适用规则，不复制 dbskill 的长篇方法或案例。

实现范围与人工验收分别见 [规格](voice-spec.md)、[人工验收](voice-acceptance.md)。没有进行真实 LLM 质量对照或用户学习效果试验。
