# tis-plain-language：简明语言与清晰表达

先读 [反馈与对话](references/voice-and-interaction.md)，控制讲评篇幅和语气。读 [通用编辑方法](references/general.md) 和 [来源与边界](references/sources.md)，再按实际目标语选择 [英文](references/en.md) 或 [简体中文](references/zh-cn.md)。

处理通知、办事说明、教学材料、健康信息、商务邮件、报告、技术文档、软件界面及译文。目标是让具体读者找到所需信息、理解意思并知道下一步；说明性文字也可以以“读懂什么”为目标，不硬塞行动号召。简明语言不等于 Easy Read（易读版）、低龄化或假定读者认知能力低。面向专家仍保留领域精度，语气随读者、关系、体裁和目的调整。

## 工作流程

1. **定目标与权限。** 沿用已有读者、用途、语言、地区、交付格式和项目规范；缺少会改变判断的信息才问。单语编辑不宣称翻译忠实；译文审校须对照原文。地区缺失仅在影响拼写、术语或格式时标待确认。客户规范优先，但不能据此改变事实或掩盖源文歧义。
2. **选改动幅度。** “检查/诊断”只指出实际问题、理由及局部建议；“润色/改清楚”默认最小修改，已有清晰文字可不改；明确要重写，或顺序与重复严重妨碍目标时，才整体重组。局部请求不扩大范围。翻译项目的段落对应、锁定文本或格式不允许重组时，保留结构并说明局限。
3. **锁定意义。** 保留事实、数字、单位、日期、责任主体、否定、条件、例外、概率、不确定性、义务/许可/建议及承诺强度；保留法律依据、医疗安全信息、术语、品牌、代码、占位符和界面字符串。不为“好懂”添因果、补未知主体或擅改医学结论。
4. **按读者组织。** 把所需结果、答案或行动放前面，再给必要依据。一个段落推进一个要点，操作按执行顺序，前提与警告紧邻相关动作。用具体主体和动词、读者熟悉且准确的词；必要术语保留并按需解释。标题、列表、表格只在帮助定位、步骤或比较时用；不机械限制句长，不要求全文短句、主动语态或项目符号。
5. **检查信息贡献。** 逐句判断是否新增事实、理由、例子、条件或必要衔接。删掉无贡献的铺垫、写作过程说明、同义复述、段尾重复结论；不是只换同义词。保留有教学、检索、安全或论证作用的重复。用户说“去 AI 味”时也执行此检查，不用词语黑名单或声称检测作者身份；人写的稿件同样适用。
6. **回查并交付。** 对照原稿/源文核对意义锁定项及指代、逻辑与术语。默认先给修改稿，再仅解释影响理解、行动、语气或忠实度的关键改动及未决问题；不逐句邀功，不再追加同义总结。无需改动就说可保留；只要稿件就只给稿件。诊断模式先给具体问题；长报告或逐项对照按用户要求展开。区分已确认语义问题、可选风格优化与待核实用法。

英文词义、搭配、语域或地区惯例有争议时用 `tis-usage-evidence` 实时核实；证据不足保留原文并标待核实。其他语言只执行可确认的通用原则，不套用英中语法。不得声称官方认证、法律/医疗审定、ASD-STE100 完全符合或未经测试的可读性提升。

CAT 的 `plain` 动作也适用于非技术领域的译文；保留 CAT JSON 与提议确认契约：`after` 放完整建议译文，无需修改则为 null，`reply` / `reason` 只补必要判断或理由，不重复整份译文。不得把简化请求当作省略源文信息的授权。

处理欧盟材料、术语概念或机构用法判断时，读 [EU 指南的任务边界与逐页依据](references/eu-guides.md)。先区分概念、实际用法和客户出版规范；不得据机构词表自动判错或更改原意。

英文译文有长插入语、隐藏条件或压缩从句问题时，读 [Clear English 句法检查](references/clear-english.md)，先核对句界权限与意义，再采用局部简化。
