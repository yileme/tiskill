# 英文目标语：简明表达检查

沿用已知英语地区要求；只有影响选择时才确认 en-US、en-GB 等变体，按客户术语表及项目风格处理拼写、日期、标点和界面术语；不凭英语是否“短”判断译文质量。Apple、Google 和 Microsoft 的品牌规则分别用于对应项目。

- 说明是谁执行动作、对哪个对象做什么；步骤写明条件、动作和可观察结果。未知施事不强行变主动。
- 一个句子承载一个主要动作或判断；复杂条件可拆句，但不能断开限制、原因或例外。
- 同一概念保持一个已核准名称；界面标签、代码、变量及占位符保持准确。不要为追求词汇变化擅自换同义词。
- 删除没有信息作用的填充词和双重表述，保留法律、技术与安全文本中的必要限定。
- 对地域拼写、真实搭配与语域争议用 `tis-usage-evidence` 查证；只能说“此项目风格偏好”时，不写成“英语错误”。

线索：[Google style: Active voice](https://developers.google.com/style/voice)、[Sentence structure](https://developers.google.com/style/sentence-structure)、[Procedures](https://developers.google.com/style/procedures)；Microsoft English (UK) Localization Style Guide §2、§4；Apple Style Guide “passive voice” 与 “localization”。特定页的链接若发生迁移，以来源索引主页定位。

通用顺序与重复检查见 [通用方法](general.md)。公众、教育、健康、行政与商务写作也使用这些原则，技术品牌规范按项目另选。

英语可检查隐藏动词（例如 make an application → apply），但名词化可用于已定义概念，不一律改掉。时态须保留真实时间关系，情态动词须保留义务、许可、建议和不确定性；简单现在时不优先于准确性。适合读者才用 you/we、缩写或较口语的表达，不把正式体改成闲聊。不要用固定词数、词源或被动语态判断错误。

Federal 的 must/should/may 区分（印刷 p.23 / PDF p.29）用于辨明强度，不授权改写法定原文；Federal 的一致术语与必要专业词（pp.43–44 / PDF pp.49–50）支持保留领域精度。HSE 的英语习惯及机构字体、数字写法只在适用场景采用。

0.9.1 补充：[EU 指南](eu-guides.md) 的 C 3–14 与 D PDF 9–10 / 印刷 3–4 支持先定读者与目的、结构优先、准确一致、保留必要被动和术语；法律与出版格式须按体裁分别判断。
