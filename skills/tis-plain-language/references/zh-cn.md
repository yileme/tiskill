# 简体中文目标语：简明表达检查

先确定简体中文读者、用途、体裁及适用地区；zh-CN 项目固定术语和界面标签。对原文意义负责，不将英式语序照搬到中文，也不因省字删除条件、否定、数量或责任主体。

- 操作步骤写清前提、动作、对象及结果；标题标明实际内容。按一个段落一个主题组织信息。
- 修复可能多指的“其”“该”“它”；术语一致，不把产品名或正式名称擅自口语化。
- 中文标点、英文变量、单位和数字混排按客户规范；没有规范时参照所选中文指南并保持篇内一致。代码、占位符及 UI 字符串保持准确。
- 避免僵硬的逐词翻译和无意义套话；长句按逻辑关系拆分，不以固定汉字数为机械阈值。
- Microsoft 中文本地化指南中的品牌术语、特殊标点要求只用于适用的 Microsoft 项目。

线索：[阮一峰《中文技术文档的写作规范》](https://github.com/ruanyf/document-style-guide) 的 text/paragraph/marks/structure；[中文技术文档写作风格指南](https://zh-style-guide.readthedocs.io/zh-cn/latest/) 的语言风格/标点；Microsoft Chinese (Simplified) Localization Style Guide §2、§4.1.13、§5。

通用顺序与重复检查见 [通用方法](general.md)。公众、教育、健康、行政与商务写作也使用这些原则，技术品牌规范按项目另选。

中文可把“进行申请的提交工作”改为“提交申请”，前提是意义相同；这不是照搬英语名词化禁令。明确“谁做什么”也不等于每句强添主语。中文通过时间词、体标记和上下文表达时间，不套英语现在时规则；“可能”“应当”“必须”“不得”“仅限”等须按原意保留。

“需要指出的是”“这意味着”“总而言之”不是禁用词：查看后文有没有新的事实、解释或限定，没有才删。论述需要的衔接可保留；不要把一段复述拆成更多标题和列表来伪装精简。通知、课堂讲义、患者说明与商务邮件分别采用适合读者关系的语气，不统一改成网络口吻。英文来源用于通用读者原则，不构成中文语法权威。
