# 公共服务英文译写

先读 [反馈与对话](references/voice-and-interaction.md)。读取 [规则与领域](references/rules.md)、[证据和冲突](references/evidence.md)；批量或本地检索再读 [CLI 契约](references/cli.md)。

支持单条中译英、原译文并列审校、批量记录。范围为公共场所和机构名称、设施标志、导向、警告、禁止、指令、简短服务通知，覆盖通则及交通、旅游、文化娱乐、体育、教育、医疗卫生、邮政电信、餐饮住宿、商业金融。长篇法律、诊疗、投资文件需另行专业流程；不能据标志标准声称专业审定或法定合规。

从已有材料提取实际位置与功能、受众、目标地区、机构正式名称、客户采用版本及既有术语表。医院内餐厅按具体行的功能选医疗或餐饮；博物馆按文化娱乐处理。缺少会改变译法的条件时提出一个具体问题，其余可做部分继续；未知项标 pending，不擅自推定。

1. 判断名称、设施、警示、禁止、指令或说明，以及标准适用范围。先读通则再读领域规则。法律依据、原意、数字、否定、责任和警告强度必须保留；正式名称先核实，客户地图有冲突就列明，不能全域替换。
2. 有本地来源时按领域检索；先读 verified 行及其原件指针、版本、表/条款、物理页和条件。candidate 只用于发现待核对来源，不能支撑定论。verified 只证明所记转录核对，并不证明当前场景适用。无配置时使用用户提供的材料，明确本次未查询本地标准；不声称标准全文随包安装。
3. 结合实际功能提出英文或最小修订。标准正文要求与资料性附录示例分开；保留允许的备选和年代语境。转录疑点回查原件，原件自身矛盾另标 source_conflict，不能直接采用或悄悄修正来源。
4. 输出译文/修改、必要理由、适用条件、标准ID/版本/条款或附录表行/PDF物理页、证据状态及待确认项。缺证据写 pending；用户材料写 user_supplied；生成建议写 proposed。单条简答，批量保留所有原始ID和行数，逐行给建议、理由、证据、条件；不虚构未处理行。
5. 批量脚本只验证结构和生成待审记录。Agent/人工需实际逐行完成译写和语义审校后填 proposedTranslation、reason、evidence，客户确认另记；不能把脚本的 null 译文当作成品。最后检查跨行一致性、数字和否定、警告等级、专名、目标地区拼写及版面换行。未检验实际标牌就不声称现场验收通过。

可选协作：tis-usage-evidence 查争议用法；tis-plain-language 优化已授权的说明；tis-inclusive-language 处理相关局部称谓。它们不是安装依赖，任何风格建议不能自动改动法定义务、医学实质、正式名称或安全警示强度。教学诊断只在用户提出教学需求时进入。

只保存用户授权的项目结果；本地知识库与公开包分离，不上传全文、完整术语库或私人路径。源文件不可改写，派生索引与核验记录保留版本。
