# tis-usage-evidence：英语译法查证

先读 [反馈与对话](references/voice-and-interaction.md)，按其规则控制讲评篇幅和语气；下文的证据、任务与保存边界仍须遵守。

从用户自有 `usage-evidence` v1.18.1 的翻译查证工作流提炼。目标是验证具体语境中的词义、词块搭配、译法、语域和地区变体。双语候选发现模式可从原文及用途开始；已有候选的用法查证至少要有候选表达和所在句；中译英时连同原文、受众、用途和目标英语变体一起看。作为 `tis-translation-diagnosis` 的证据层使用，也可独立回答“这个译法能用吗”。

## 双语候选发现与回查

用户说“找双语译例/回查译法”或尚无译法候选时，先读 [双语检索与溯源](references/bilingual-retrieval.md)，按译之有道、热词译、Linguee 的来源角色发现候选，再接下方目标语用法查证。原始出处核实、句对读取/对齐与本句适用性分别记录；遵守保密查询与反自动化停止边界。

## 专业术语与概念查证

用户要核对中文规范术语、英汉对应、学科定义或同名异义时，先读 [术语在线检索协议](references/termonline.md)，用官网真实条目核对概念、学科、来源与可见公布字段，再按需要补目标语词典/领域语料。区分审定公布、征求意见、百科及未明确身份；已读条目不等于公布信息已独立核实。客户简报优先约束当前任务，与来源冲突须显明并确认，不静默改写；术语命中不能独自证明本句搭配和语域。

## 查证流程

1. **圈定待证命题**：先区分原文与译文直接可核的意义变化（数字、否定、遗漏等）、可查词义/目标语用法、依赖客户术语表或领域事实的判断。只有后两类需要外部证据；不要为明显的数字错译硬搜语料。先提出合理的候选与具体问题（是词义、搭配、语域还是学科用法）。
2. **按问题选 1–3 个合适来源**，路径见 `references/sources.md`。词义看目标义项原话；搭配优先词典例句与语料对照：真实句中用法查 SkELL Examples（concordance），按语法关系发现搭配查 SkELL Word Sketch（操作与离线入口见 [SkELL 检索协议](references/skell.md)），填空与频率对比查 Linggle/Ngram；译法可用 Linguee 的双语词典与对齐例句发现候选，再核对原始来源链接、两侧上下文、领域、来源质量、译向及是否同一义项，并用目标语词典/语料复核；语域看词典标注和目标文本领域语料。学术用法优先相应学科资料。来源不能访问时可切换来源，但报告未能查证之处。
3. **核实而非转述检索结果**：打开真实页面，记录实际 URL、查询式、短小的逐字释义/例句或可复核的频率值及访问范围。频率偏好不等于错误；单一例句不等于通用惯例。源冲突时先比较语境、地区、年代和语域；无法化解就写“证据不足”。词典未收录只说明该词典未收录，不据此宣告表达不存在。SkELL 自动从真实语料中筛选例句、提取搭配，与模型生成句子不同；仍须核对义项、语法关系与语料覆盖，不能把自动结果当成人工审定的规范。不要把模型生成例句、自动生成的并列语料或搜索摘要当成权威译法。
4. **给结论并交还诊断**：分别写证据事实和在本句的推断，说明原译可用、有条件可用、证据支持替换，或待核实。每个影响点评的用法判断附 1–2 条最强的短证据和访问到的词条或查询页的真实 Markdown 链接。给可以直接代入本句的修改和适用条件。确实没有外部证据时，不把“我觉得不地道”列为必改错误。

## 在笔译诊断中使用

当点评理由涉及“这个英文义项、搭配、习语、语域或译法是否成立”时，先运行本子技能的查证流程，再确定 `tis-translation-diagnosis` 的类别、修改优先级和替换方案。诊断表中的“依据”分别标明“原文对照”或“用法查证”，用法证据需要真实行内链接。可接受的多个译法要明确保留。原文对照、词典或语料、客户术语表各能证明不同事情，不能互相替代。大篇幅材料先查对结论影响最大的疑点；其余标明待核实和覆盖范围。

原项目为用户自有 MIT 项目 `xionglingsong/usage-evidence`；本子技能是适合 tiskill 的精简分支。原项目的其他教学与学术写作模块仍由原项目维护；不宣称已经移植其全部能力。`scripts/ngram.mjs` 归原项目 MIT 许可，运行前检查 Node.js、curl 可用；Ngram 的书籍语料止于 2019 年，不能单独证明当代口语或专业语域。所有 URL、频率、引语都须本次实查，不沿用参考文件中的历史例子作为即时证据。

## 可保存的证据输出与状态

需要保存或导出证据卡时，每条证据按以下结构输出；日常查词直接回答本句能否使用、关键引文与链接、适用限制，不强制展示空字段。卡片字段如下（无材料的字段写“待核实”或留空，不补造）：
- 表达、当前语境、逐字短引文、实际来源 HTTP(S) URL、查询词和访问日期；视频时间点仅填写本次实际定位的位置。
- 领域、语域、适用范围、解释与限制；事实和本句推断分开。
- 状态：unverified（未取得可核原文）、text_read（实际读过对应原文）、audio_checked（实际听过对应音频）；核对者及方式分别说明为本环境实际读取/听取，或用户明确确认。

视频口语、语调和跟读材料优先实际打开 YouGlish / PlayPhrase，再按需要回到原视频；不要用 Ngram 的图书频率替代口语证据。只看见字幕可标 text_read，不能据此评价发音或标 audio_checked。来源打不开、登录/地区/反自动化限制或内容已下架，就标待核实并说明缺口。检索入口、有效 URL、引号加链接的格式检查都不能证明证据已核实。


## 可选 Obsidian 保存

查证、表达积累和练习复盘属于现有 Obsidian vault 内的 tiskill 文件夹，不放入 CAT。默认在对话中输出；用户明确要求保存才写入。先读取 `~/.tiskill/library.json` 的 `path`（配置不存在时不猜测私人路径），用 `~/.tiskill/source.json` 的 `repo` 找到仓库及 `docs/library.md` 的 JSON 输入契约。可直接按目录内模板写 Markdown，或运行 `python3 <repo>/tools/library.py save --input <record.json> --confirm`；此参数只表达已有保存授权，不代替实际核实。

查证保存到 `01-查证记录`，表达到 `02-表达积累`，回答和自评到 `03-练习复盘`。文件名 `YYYYMMDD_主题_V01.md`，保留 ID、日期、来源、限制与核对者；待核实 `unverified` 与 `text_read` / `audio_checked` 分开。CLI 已核实状态要求用户确实核对并明确确认，不从链接、字幕或生成内容推定。练习可引用已存记录的 `sourceId`，CLI 保存当时完整快照；没有来源时保持待核实，不编造来源。模型练习题标作练习，不作为真实引文。保存后检查文件存在，返回实际文件链接；同名使用新版本，已有 ID 不覆盖。

处理欧盟材料、术语概念或机构用法判断时，读 [EU 指南的任务边界与逐页依据](references/eu-guides.md)。先区分概念、实际用法和客户出版规范；不得据机构词表自动判错或更改原意。
