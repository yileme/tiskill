# 双语译例：发现候选，再回查译法

用户说“找双语译例”“回查译法”、只有原文还没有候选，进入本模式；已经有英文候选时继续既有词典/目标语语料流程。使用已有原文、领域、受众与用途，必要时说明缺少的条件。先找 1–3 条相关译例，再核原始出处与目标语用法，不把双语命中直接判作最佳译法。

## 精确检索与访问边界

保留 Google `site:reciyi.com "人民当家作主"` 方法；其他两站替换为配置中的完整 host。只对参数值作 UTF-8 URL 编码（引号、中文、空格、&、+、#、% 均编码），不把未编码用户文本拼进 URL。`scripts/bilingual_queries.py --source reciyi` 从标准输入读公开/获准短语，离线生成 Google/Bing 查询、网站首页及 Linguee 查询 URL；只需 Python 3 标准库，运行前检查可用性。它不联网、不爬取、不调用 API、不打开浏览器、不记录日志；输出 `not_requested`，生成 URL 从不算已查证。输出含查询文本，勿发布到日志或共享工单。

客户保密文本、未公开项目名称和可识别片段不得未经授权范围直接送搜索引擎或外部站点。采用已获准的公共术语，或在本地资料核对；不能假定“帮我翻译”授权公开全文搜索。程序不能自动判断文本是否保密。

一次普通抓取仅有 JS 空壳时记 `js_required`，可用正常浏览器加载一次。出现异常流量、CAPTCHA 或 HTTP 429 即停止该站自动化；429 记 `rate_limited`，保留并遵守 Retry-After（若有），本轮不自动重试。禁止代理轮换、令牌伪装、验证码解算、冒充 Googlebot 或关闭 TLS 校验。只有用户愿意时由其手动完成验证；否则继续独立的 Bing site 检索或其他合法引擎、网站公开栏目和原始机构网站，不借另一通道重试被阻挡端点。连接/TLS 错误不是 CAPTCHA；正常 www 首页可独立检查，不能降低传输安全。

每次访问分别记录实际 URL、查询、访问日期、方法、状态和限制：

- `not_requested`：只生成入口，未访问。
- `js_required`：仅有脚本壳，尚无实际结果。
- `captcha`：验证码或异常流量验证页；不把它记作无结果。
- `rate_limited`：明确 429/限流；记录 Retry-After。
- `login_required`：页面明确要求登录；不尝试登录绕过。
- `empty_results`：正常结果页明确显示无匹配；空壳/无正文不能这样标。
- `results_read`：实际读到结果列表；逐项核域名及短语，另记 relevantResults，离题结果不算证据。
- `text_read`：实际读到对应正文，注明读的是聚合站还是原始文献。
- `fetch_failed`：连接、TLS、超时、HTTP 错误或无法取得结果，说明原因；不推断零命中。

备用路线不保证当前可访问；搜索摘要只提供线索。不要引用总命中数证明译法正确。

## 证据链与本句适用性

1. 保留短而完整的双语句对（长句改选更短完整句），逐字引语不得擅改数字、标点、日期、限定或来源行。页面已有省略号必须保留并标明“不完整”；不要拼接成完整原话。助手改写单列，不能放进引号冒充译例。
2. 分别记录聚合站 URL/名称、页面所称原始出版者、原文链接和译文链接、标题、原始出版日期、聚合发布日期、访问日期、原文来源行原样文字及页码/段落定位。找不到字段留空或 unknown，不从域名、主题、人物身份猜权威性。
3. 打开原始机构文件，比对两侧上下文、日期和版本。记录 `originalVerification`（unverified/verified）及核对方式；聚合正文读过不等于原文已核。翻译方向为 zh-en/en-zh/unknown，并附依据；不能据左右位置或查询语言推断。
4. 分开判断 reading（实际读到什么）、alignment（句对是否完整对应）、applicability（当前领域、受众、语域、年代、地区是否可迁移）。某机构确实使用该译法，只证明限定语境的使用；仍需既有目标语词典/领域语料查证。缺口不自动判错。
5. 按原始文献 ID/规范 URL + 版本去重，同一讲话在多个站转载只算一份原始证据。出处未知的复制文本保守合并，不能凭多个域名增加独立证据数。

## 简短交付模板

> 候选：〈译法〉。原文：“〈完整短句〉”；译例：“〈完整短句〉”。
> 发现于：〈聚合站名称及实际 URL，交付时转为行内链接〉；原始出版者：〈已核名称或待核实〉；〈原文/译文实际链接，未知则不造链接〉。
> 事实：〈读到的文字、日期、来源行〉。核对：〈聚合/原文读取情况；对齐；译向依据〉。
> 本句：〈为什么可用或不适用〉；限制：〈领域、语域、出处或目标语查证缺口〉。
> 建议改写（助手生成，非原文）：〈仅在需要时给出〉。

未取到句对时交付“该入口受限/无相关结果，尚无可引用双语证据”，列实际备用路径状态，不补造候选引文。实查示例与离线测试分开见仓库 docs/bilingual-acceptance.md。

## 可选保存

仅用户明确要求保存才写 Obsidian；开发测试仅用临时目录。沿用既有 evidence 字段，在可选 `bilingual` JSON 内保存双语和出处，不建数据库或 CAT 标签页。字段契约见仓库 docs/library.md。顶层 verification 沿用 CLI 的用户确认规则：Agent 读过网页可在 bilingual.reading 中如实记录，不能自动设置 userConfirmed 或提升顶层状态。元数据保存只是保全声明，不验证其真实性。
